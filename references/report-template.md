# 报告模板

技能执行完成后，按以下格式生成精炼报告。报告包含 3 个部分，不添加冗余信息。

---

## 模板

```markdown
# 招聘岗位筛选结果

## 一、任务参数

| 参数 | 值 |
|------|-----|
| 触发模式 | {workflow/atomic} |
| 勾选模式 | {MODE描述} |
| 搜索词 | {KEYWORD} |
| URL 来源 | {JSON文件名 / 用户直接输入} |
| 站点数 | {N} |

## 二、匹配结果（标题含"{KEYWORD}"的岗位）

| # | 网站 | 岗位链接 |
|---|------|---------|
| 1 | {企业名} | {岗位详情页 URL} |
| ... | ... | ... |

> 共 {N} 个匹配岗位

（如无匹配，显示"无匹配岗位"）

## 三、不匹配结果

| # | 网站 | 检索状态 | 说明 | 网站链接 |
|---|------|---------|------|---------|
| 1 | {企业名} | {状态} | {说明} | {原始 URL} |
| ... | ... | ... | ... | ... |

> 共 {N} 个站点无匹配

（如无不匹配站点，显示"全部站点均有匹配"）

## 四、注意事项

{站点适配问题}
{错误处理经验}
{供下次执行参考的要点}
```

---

## 字段说明

### 匹配结果 — 链接规则

| 情况 | 链接列填什么 |
|------|------------|
| 搜索成功 + 有匹配 | **岗位详情页链接**（从搜索结果中提取的实际 URL） |

### 不匹配结果 — 各字段说明

| 字段 | 填写规则 |
|------|---------|
| 网站 | 企业名或站点标识 |
| 检索状态 | `搜索成功` / `搜索失败` / `搜索框未找到` / `页面加载失败` / `跳过` |
| 说明 | 简要说明原因（如"22个岗位均为AI/算法类，无前端" / "页面需登录" / "链接非岗位列表页"） |
| 网站链接 | **网站原始 URL**（用户提供的或 JSON 中的链接） |

### 检索状态枚举值

| 状态 | 含义 | 说明示例 |
|------|------|---------|
| `搜索成功` | 搜索正常执行，但无匹配 | "22个岗位均为AI/算法类，无前端" |
| `搜索失败` | 搜索功能不可用 | "搜索框输入后未触发过滤" |
| `搜索框未找到` | 页面无搜索功能 | "该页面无搜索输入框" |
| `页面加载失败` | 页面无法正常打开 | "页面返回404" 或 "需内网访问" |
| `跳过` | 不适合检索的链接 | "链接为公众号文章，非岗位列表页" |

## 示例 A：工作流模式

```markdown
# 招聘岗位筛选结果

## 一、任务参数

| 参数 | 值 |
|------|-----|
| 触发模式 | workflow（工作流模式） |
| 勾选模式 | 3（不勾选） |
| 搜索词 | 前端 |
| URL 来源 | smartsheet_filter_result.json |
| 站点数 | 3 |

## 二、匹配结果（标题含"前端"的岗位）

| # | 网站 | 岗位链接 |
|---|------|---------|
| 1 | 拼多多集团 | https://careers.pddglobalhr.com/campus/grad/detail?positionId=xxx |
| 2 | 微步在线 | https://app.mokahr.com/m/campus_apply/threatbook/39679#/job/xxx |

> 共 2 个匹配岗位

## 三、不匹配结果

| # | 网站 | 检索状态 | 说明 | 网站链接 |
|---|------|---------|------|---------|
| 1 | 科大讯飞 | 搜索成功 | 97个岗位均为AI/算法类，无前端 | https://iflytek.zhiye.com/campus/jobs |
| 2 | 腾讯音乐 | 跳过 | 页面需登录后才能查看 | https://join.tencentmusic.com/campus |

> 共 2 个站点无匹配

## 四、注意事项

1. 拼多多：默认列表不展示全部岗位，必须通过搜索框才能找到前端岗位。
2. 科大讯飞：搜索功能正常，但搜索结果 97 条中无前端相关岗位。
3. 腾讯音乐：需要登录态，未检索。
4. 空结果处理：直接跳过，未尝试分页或 URL 参数兜底。
```

## 示例 B：原子模式

```markdown
# 招聘岗位筛选结果

## 一、任务参数

| 参数 | 值 |
|------|-----|
| 触发模式 | atomic（原子模式） |
| 勾选模式 | 3（不勾选） |
| 搜索词 | 算法 |
| URL 来源 | 用户直接输入 |
| 站点数 | 1 |

## 二、匹配结果（标题含"算法"的岗位）

| # | 网站 | 岗位链接 |
|---|------|---------|
| 1 | 合合信息(INTSIG) | https://intsig.zhiye.com/campus/jobs/detail/xxx |
| 2 | 合合信息(INTSIG) | https://intsig.zhiye.com/campus/jobs/detail/yyy |

> 共 2 个匹配岗位

## 三、不匹配结果

无（全部站点均有匹配）

## 四、注意事项

1. 用户直接提供 URL，未指定招聘项目模式，默认 MODE=3（不勾选）。
2. INTSIG 搜索功能正常。
3. 只检查了第一页结果。
```

---

## 格式规则

1. **报告文件名**：`{KEYWORD}岗位检索报告.md`（如 `前端岗位检索报告.md`）
2. **保存位置**：当前工作目录的 `output/` 目录
3. **链接格式**：完整 URL，不截断
4. **表格顺序**：匹配结果在前，不匹配结果在后；同类别内按企业名排序
5. **注意事项**：只记录对下次执行有参考价值的信息，不记录执行过程细节
6. **链接规则**：
   - 匹配成功 → 岗位详情页链接
   - 搜索失败/跳过/无匹配 → 网站原始 URL
7. **空结果**：不尝试兜底策略，直接如实记录
