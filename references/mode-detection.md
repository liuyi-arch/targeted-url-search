# 触发模式检测参考

本文件描述 `browser-use-job-search` 技能的两种触发模式的检测规则、关键词匹配和输入提取逻辑。

---

## 一、模式定义

| 模式 | 标识 | 触发条件 | URL 来源 |
|------|------|---------|---------|
| 工作流模式 | `workflow` | 用户明确提及 "targeted-url-search" | 上一节点输出的 JSON 文件 |
| 原子模式 | `atomic` | 用户提示词包含"在特定网站检索特定内容"语义 | 用户直接输入 |

---

## 二、工作流模式触发词

### 精确匹配

以下字符串出现在用户提示词中时，触发工作流模式：

- `targeted-url-search`（不区分大小写）
- `targeted url search`（不区分大小写）

### 示例提示词

| 用户输入 | 是否触发 | 说明 |
|---------|---------|------|
| "用 targeted-url-search 帮我搜前端岗位" | ✅ | 直接提及技能名 |
| "运行 targeted-url-search" | ✅ | 直接提及技能名 |
| "targeted-url-search 搜索 算法岗" | ✅ | 直接提及技能名 |

---

## 三、原子模式触发词

### 语义匹配

用户提示词包含以下语义模式时，触发原子模式：

| 语义模式 | 示例 |
|---------|------|
| "在...网站...检索/搜索..." | "在飞书招聘上搜索前端岗位" |
| "帮我看...链接...有没有...岗位" | "帮我看看这个链接里有没有算法岗" |
| "打开...网址...搜索..." | "打开 https://xxx.com 搜索后端" |
| "...网站...找...职位/岗位" | "这个招聘网站帮我找产品经理职位" |
| "...url...检索...关键词" | "用这个url检索 前端 关键词" |

### 关键词组合规则

以下关键词组合出现时判定为原子模式：

1. **网站/链接/网址/URL** + **搜索/检索/找/查** + **岗位/职位/关键词**
2. **打开** + **URL** + **搜索/检索**

### 示例提示词

| 用户输入 | 是否触发 | 提取结果 |
|---------|---------|---------|
| "在 https://xxx.com 上搜索前端岗位" | ✅ | URL=https://xxx.com, KEYWORD=前端 |
| "帮我看看 https://dexmal-inc.jobs.feishu.cn 有没有算法岗" | ✅ | URL=..., KEYWORD=算法 |
| "打开这个网址 https://intsig.zhiye.com/campus/jobs 搜产品" | ✅ | URL=..., KEYWORD=产品 |

### 不触发的示例

| 用户输入 | 原因 |
|---------|------|
| "搜索前端岗位" | 无网站/URL，不满足"在特定网站"语义 |
| "帮我找前端工作" | 无网站/URL |
| "targeted-url-search" | 匹配工作流模式，优先判定为工作流 |

---

## 四、触发优先级

如果用户提示词同时满足两种模式条件，**优先判定为工作流模式**。

示例：
- "用 targeted-url-search 在 https://xxx.com 搜索前端" → 工作流模式（因为提及了 targeted-url-search）

---

## 五、输入提取规则

### URL 提取

从用户提示词中匹配 URL 的正则模式：

```
https?://[^\s<>"'，。、）)]+
```

- 支持多个 URL（每行或逗号/空格分隔）
- URL 中的中文标点会截断（如句号、逗号）

### 关键词提取

从提示词中提取搜索关键词的方法：

1. **显式关键词**：提示词中"搜索/检索/找/查"后面的名词（如"前端"、"算法"、"产品"）
2. **引号内容**：提示词中被引号包裹的内容（如 `搜索"前端开发"` → KEYWORD=前端开发）
3. **岗位类型词**：常见岗位类型词库匹配（前端、后端、算法、产品、测试、运维、数据、安全、嵌入式、客户端、移动端...）

### 招聘项目模式提取（补充信息）

从提示词中识别招聘项目类型：

| 关键词 | MODE |
|--------|------|
| 校招、校园招聘、秋招、春招、应届 | 1 |
| 实习、日常实习、暑假实习、暑期实习 | 2 |
| 社招、社会招聘 | 1（归入校招/全职类） |
| 未提及 | 3（默认不勾选） |

### 排除序号提取（工作流模式专用）

从提示词中识别用户排除的网站序号：

| 提示词 | 提取结果 |
|--------|---------|
| "第2个不用查" | EXCLUDE_INDICES=[2] |
| "排除第1和第3个" | EXCLUDE_INDICES=[1,3] |
| "1、3不用" | EXCLUDE_INDICES=[1,3] |

## 六、校验失败时的重新询问文案

### 工作流模式

当必填字段缺失时，使用 `AskUserQuestion` 工具：

```
问题: "是否对上一个节点输出网站进行全量检索？"
header: "检索范围"
选项:
  - label: "全量检索"
    description: "对上一节点输出的所有网站进行检索"
  - label: "选择性检索"
    description: "排除部分网站，只检索指定的网站"
```

选择后继续追问：

- **全量检索** → "请给出检索关键词和补充信息（可选，如校招/实习）"
- **选择性检索** → "请说明哪些网页不需要检索（给出序号）、检索关键词、补充信息（可选）"

### 原子模式

当必填字段缺失时，直接提示：

- **URL 缺失** → "未检测到待检索网站网址。请输入待检索网站网址、检索关键词、其余补充信息（可选）。"
- **KEYWORD 缺失** → "未检测到检索关键词。请输入待检索网站网址、检索关键词、其余补充信息（可选）。"
- **两者都缺失** → "请输入待检索网站网址、检索关键词、其余补充信息（可选）。"

## 七、流程图

```
用户提示词
    │
    ├─ 含 "targeted-url-search"？
    │     ├─ 是 → 工作流模式
    │     │         │
    │     │         ├─ 从提示词提取 JSON_FILE / KEYWORD / EXCLUDE / SUPPLEMENTARY
    │     │         ├─ 校验: JSON存在? + KEYWORD存在?
    │     │         │     ├─ 通过 → Step 0d 解析 MODE → 执行流程
    │     │         │     └─ 失败 → AskUserQuestion(全量/选择性) → 回到校验
    │     │         │
    │     └─ 否 ↓
    │
    ├─ 含 "在...网站...检索" 语义？
    │     ├─ 是 → 原子模式
    │     │         │
    │     │         ├─ 从提示词提取 URL_LIST / KEYWORD / SUPPLEMENTARY
    │     │         ├─ 校验: URL存在? + KEYWORD存在?
    │     │         │     ├─ 通过 → Step 0d 解析 MODE → 执行流程
    │     │         │     └─ 失败 → 提示用户补充 → 回到校验
    │     │         │
    │     └─ 否 → 不触发本技能
```
